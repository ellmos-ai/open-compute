================================================================================
1. EXECUTIVE SUMMARY & COMPLIANCE ASSURANCE
================================================================================

open-compute uses an offline default mock loop, user-mode execution
(RunAsInvoker), and safety policies. Configured provider backends and Cowork
may use external services; MCP hosts receive observation content. The core
agent loop has zero mandatory external runtime dependencies and executes
entirely within the Python standard library. Optional extras (anthropic, openai,
playwright, mss, Pillow, uiautomation, windows-capture, watchdog, clirec, mcp)
are dynamically and lazily imported only when explicitly selected by the
operator.

This inventory records license identifiers listed for the current dependencies.
It is not a blanket guarantee for future or transitive dependencies, or a
certification of operational safety. Consult the applicable package license files.
Canonical copyright and ecosystem attributions are formally preserved in the
root NOTICE file.

3. LICENSE INVENTORY, USER-MODE EXECUTION & NETWORK BOUNDARIES
================================================================================

1. Zero-Copyleft Inventory Scope:
   The recorded license identifiers describe the listed current dependencies.
   They do not establish a blanket guarantee for future or transitive packages;
   consult each applicable license file.

2. Unprivileged Execution (RunAsInvoker):
   open-compute enforces unprivileged user-mode execution under INV-USR-06.
   All GUI interactions, coordinate normalizations, and action dispatches operate
   strictly within non-elevated user context without requiring administrative
   or root privileges.

3. Zero-Egress Scope:
   Under INV-EGR-07, the default mock loop is offline. Configured providers,
   Cowork workers and MCP hosts have separate transmission boundaries. The
   package does not intentionally persist provider keys; captures/actions may
   contain sensitive data and can be saved or returned to a host/provider.
   Profile filtering applies only to explicit filtered MCP calls. The
   configured MCP grace wait defaults to 4s with a 120s activity cooldown;
   operators can set 0. Direct CLI/SDK execution does not use that MCP wait.
